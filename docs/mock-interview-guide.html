프롬프트
웹캠 모의 면접 + AI 피드백 서비스를 이 프로젝트에 만들려고 해. 아직 코드는 쓰지 말고 설계 문서 docs/PLAN.md 만 작성해줘.

[서비스]
- 사용자가 분야(예: 백엔드 개발자, 마케팅, 간호사, 공기업 행정), 수준(신입/경력), 질문 수(3~10), 채용 공고 내용(선택)을 입력하면 AI 가 면접 질문 세트를 만든다. 질문마다 평가 의도(무엇을 보려는 질문인지)도 만든다.
- 면접자가 카메라·마이크를 점검하고 준비되면 면접을 시작한다. 질문을 화면에 띄우고 음성으로 읽어 준 뒤 답변을 녹음한다 (질문당 최대 답변 시간 기본 120초, "답변 완료" 버튼).
- 답변하는 동안 브라우저에서 영상으로 자세·표정·시선·제스처를 분석하고, 답변 음성은 서버에서 텍스트로 바꿔 말하기 속도·침묵·군말을 계산한다.
- 모든 질문이 끝나면 답변 내용 + 말하기 지표 + 비언어 지표를 종합한 피드백 리포트를 보여 준다. 지난 면접 기록을 다시 볼 수 있다.

[정해 둔 기술 결정] 이대로 설계해줘.
- 영상은 서버로 보내지 않는다. 브라우저에서 @mediapipe/tasks-vision 의 FaceLandmarker(blendshapes, 얼굴 변환 행렬)와 PoseLandmarker(lite)로 분석하고, 질문마다 요약 지표 JSON 만 보낸다.
- 음성은 질문마다 MediaRecorder 로 녹음해 multipart 로 업로드하고, 백엔드가 OpenAI 호환 음성 인식 API(response_format=verbose_json, 단어 타임스탬프)로 텍스트와 단어별 시각을 받는다. 제공자는 STT_PROVIDER 설정 하나로 고른다: openai(기본, whisper-1), groq(무료 등급, whisper-large-v3-turbo), local(Compose 의 speaches 컨테이너에서 faster-whisper 실행, 무료). 오디오 파일은 인식 후 저장하지 않는다.
- 질문 읽기는 브라우저 speechSynthesis(ko-KR).
- 질문 생성·피드백은 기존 app/ai 의 ChatModel(ChatModelDep)로만 부르고, model.complete(..., json_mode=True) 로 JSON 을 받아 pydantic 으로 검증한다. 검증 실패 시 1회 재시도, 그래도 실패하면 상태 FAILED 와 한국어 오류 메시지를 저장한다 (요청 안에서 바로 답하는 호출이면 502). 프롬프트는 OpenAI 와 Ollama 의 로컬 모델(exaone3.5:7.8b 등 7B 급) 둘 다에서 통하도록 짧고 구체적으로 쓰고 출력 예시 JSON 을 넣는다. 제공자는 .env 의 AI_PROVIDER 로만 바뀌고 코드에 제공자 분기를 두지 않는다.
- 오래 걸리는 작업(질문 생성, 답변별 피드백, 종합 리포트)은 요청 안에서 기다리지 않고 FastAPI BackgroundTasks 로 돌린다. 상태(PENDING/RUNNING/DONE/FAILED)와 오류 메시지를 저장하고, 화면은 상태를 다시 조회(폴링 2~3초)한다. 같은 작업이 겹쳐 돌지 않게 한다.
- 지표 판정 기준(임계값)은 백엔드 상수·설정과 프론트 상수 한곳에 모아 바꿀 수 있게 한다. 비언어 지표는 "카메라 영상으로 추정한 참고값"이라고 화면에 표시한다.

11⑥ 피드백과 결과 리포트

프롬프트

[백엔드: 답변별 피드백]
- 답변 업로드(단계 ④ 엔드포인트)가 저장을 마치면 BackgroundTasks 로 답변별 피드백을 만든다. 입력: 질문, 평가 의도, transcript, 말하기 지표, 비언어 지표. 출력 JSON: scores{content, structure, delivery, nonverbal}(0~100), strengths[], improvements[], betterAnswer(더 나은 답변 예시). 답변 행에 feedback_status(PENDING/RUNNING/DONE/FAILED), feedback(JSON), prompt_version 을 저장한다. 업로드 응답은 기다리지 않고 바로 돌려준다.
- 지표를 그대로 LLM 에 넘기지 말고, 판정 기준 상수(PLAN 4·5절)로 먼저 "말하기 속도: 빠름(분당 380음절, 기준 250~350)"처럼 판정 문장으로 바꿔서 넣는다. 기준값은 한 파일에 모은다. 빈 답변은 LLM 을 부르지 않고 내용 점수 0 과 "답변 없음" 피드백으로 저장한다.

[백엔드: 종합 리포트]
- POST /api/interviews/{id}/finish: 상태를 COMPLETED 로 바꾸고 BackgroundTasks 로 리포트 생성을 시작한다 (report_status PENDING → RUNNING → DONE/FAILED). 리포트 작업은 아직 피드백이 없거나 실패한 답변을 먼저 만들고(최대 3개씩 순서대로), 답변별 피드백 + 지표 평균으로 종합 리포트 JSON(overallScore, summary, categoryScores, topStrengths[3], topImprovements[3], practicePlan[]) 을 만들어 저장한다. 루브릭(점수 기준)은 프롬프트에 명시한다. 이미 RUNNING 이면 다시 시작하지 않는다(409 대신 현재 상태 반환).
- GET /api/interviews/{id}/report: report_status, 리포트, 답변별 피드백 상태를 함께 돌려준다. 실패했으면 오류 메시지(한국어)와 다시 만들기 가능 여부.
- 테스트: 가짜 모델로 정상, JSON 깨짐 재시도 성공, 두 번 실패 FAILED 저장, 빈 답변 질문, RUNNING 중 중복 finish, 다른 사용자 404. BackgroundTasks 는 TestClient 가 응답 뒤 바로 실행하므로 그대로 검증 가능.

[프론트엔드: 결과 화면 /interviews/:id/result]
- report_status 가 DONE 이 될 때까지 2~3초마다 다시 조회하며 "피드백 만드는 중 (3/5 답변 완료)" 진행 표시. FAILED 면 오류와 "다시 만들기" 버튼(finish 재호출). 로컬 모델에서는 몇 분 걸릴 수 있다는 안내 문구.
- 종합 점수, 영역별 점수 막대(차트 라이브러리 없이, 색은 점수 구간에 따라 success / warning / destructive 토큰), 요약, 강점·개선점 Top 3, 연습 계획.
- 말하기 지표 표와 비언어 지표 표: 값, 기준 범위, 판정은 components/ui 의 Badge(tone: success=적정, warning=주의). "자세·표정 지표는 카메라 영상으로 추정한 참고값입니다" 문구.
- 질문별 접이식 카드: 질문, 내 답변 텍스트, 점수, 피드백, 더 나은 답변 예시. 피드백이 아직이면 카드 안에 진행 표시.

증상원인과 해결
카메라가 검은 화면이거나 권한을 묻지 않음OS 가 브라우저를 막고 있을 수 있습니다. Windows: 설정 → 개인 정보 및 보안 → 카메라(마이크) → 데스크톱 앱 접근 허용. macOS: 시스템 설정 → 개인정보 보호 및 보안 → 카메라(마이크) → Chrome 켜기 후 브라우저 재시작. Zoom·Teams 처럼 카메라를 쓰는 앱도 닫습니다.
휴대폰이나 다른 PC 에서 http://192.168… 로 열면 카메라가 안 됨브라우저는 localhost 나 https 에서만 카메라를 허용합니다. 같은 PC 의 localhost 로 확인하세요.
한국어 목소리가 안 나옴Windows: 설정 → 시간 및 언어 → 음성 → 음성 추가 → 한국어. macOS: 시스템 설정 → 손쉬운 사용 → 읽기 및 말하기 → 시스템 목소리에서 한국어(예: Yuna) 받기. 설치 후 브라우저를 다시 시작합니다.
자세·표정 분석 모델이 로딩되지 않음회사·학교 네트워크가 cdn.jsdelivr.net 이나 storage.googleapis.com 을 막는 경우입니다. 프롬프트: "MediaPipe wasm 과 모델 파일을 frontend/public/mediapipe/ 에 두고 거기서 읽도록 바꿔줘. 내려받는 스크립트도 만들어줘."
업로드할 때 413 오류, 또는 질문 생성이 504 로 끊김 (Docker 실행에서만)예전 템플릿으로 만든 프로젝트입니다. frontend/nginx.conf 의 location /api/ 에 client_max_body_size 25m 과 proxy_read_timeout 300s 를 넣고 Docker 를 다시 빌드합니다 (새 템플릿은 기본 포함).
업로드가 400 "JSON 형식을 확인해 주세요"client.ts 가 FormData 에도 Content-Type: application/json 을 넣고 있습니다. 새 템플릿은 고쳐져 있고, 예전 템플릿이면 9단계 프롬프트의 client.ts 항목이 고칩니다.
백엔드 시작 시 "Form data requires python-multipart"예전 템플릿입니다. cd backend 후 uv add python-multipart, pyproject.toml 과 uv.lock 둘 다 커밋.
Ollama: AI 요청이 502 이고 로그에 "연결 실패 (http://ollama:11434…)".env 의 COMPOSE_PROFILES 가 비어 있어 Ollama 컨테이너가 안 떴습니다 (구성 A·B). ollama 또는 ollama-gpu 로 두고 다시 make up. 구성 C·D 로 쓰려던 것이면 OLLAMA_DOCKER_URL 줄의 # 을 지웠는지 확인.
Ollama(C): ssh 가 "bind: Address already in use" 로 터널을 못 엶내 PC 에 Ollama 앱이 설치되어 11434 포트를 이미 쓰고 있습니다. 앱을 끄거나, 터널을 -L 11435:localhost:11434 로 열고 .env 의 OLLAMA_DOCKER_URL·OLLAMA_BASE_URL 포트를 11435 로 맞춥니다.
Ollama(C): 502 이고 로그에 "연결 실패 (http://host.docker.internal:11434…)"SSH 터널 창이 닫혔거나 PC 가 절전에서 깨어나며 끊긴 경우가 대부분입니다. ssh -N -L 11434:localhost:11434 사용자@서버주소 를 다시 실행하고 브라우저에서 http://localhost:11434/api/tags 가 열리는지 확인. 서버 주소를 직접 적은 경우는 서버의 Ollama 가 OLLAMA_HOST=0.0.0.0 으로 떠 있는지와 방화벽의 11434 포트를 확인. macOS 앱(D)은 앱이 켜져 있는지.
Ollama: 로그에 "HTTP 404 … model … not found"모델을 아직 안 받았습니다. A·B 는 make ai-model(Windows docker compose exec ollama ollama pull exaone3.5:7.8b, B 는 ollama-gpu), C 는 원격 서버에서 ollama pull exaone3.5:7.8b. OLLAMA_MODEL 을 바꿨다면 그 이름으로 다시 받고, .env 의 이름과 ollama list 의 이름(태그 포함)이 같은지 확인.
Ollama: GPU 프로필(B)인데 느리고 서버의 nvidia-smi 에 안 보임서버에서 docker run --rm --gpus all ubuntu nvidia-smi 가 실패하면 Docker 가 GPU 를 못 씁니다. Windows 는 Docker Desktop 설정에서 WSL2 백엔드 확인과 NVIDIA 드라이버 업데이트, Linux 는 NVIDIA Container Toolkit 설치 후 Docker 재시작.
Ollama: 질문 생성이 자주 502 (JSON 형식 오류)모델이 작아 형식을 못 지키는 경우입니다. OLLAMA_MODEL 을 exaone3.5:32b(원격 GPU) 나 gemma3:12b 로 올리거나, 그 단계만 AI_PROVIDER=openai 로 돌립니다. 백엔드 로그에 모델 응답 앞부분이 남습니다.
Ollama: 메모리 부족으로 컨테이너가 꺼짐Docker Desktop 의 메모리 한도(설정 → Resources)를 모델 크기 + 2GB 이상으로 올리거나 더 작은 모델(exaone3.5:2.4b)로 바꿉니다.
로컬 음성 인식(local)이 연결 실패make stt-up(Windows docker compose --profile stt up -d stt)으로 stt 컨테이너를 켰는지, 처음 실행에서 모델 내려받기가 끝났는지 docker compose logs -f stt 로 확인합니다. 개발 모드면 LOCAL_STT_BASE_URL=http://localhost:8001/v1.
Groq 음성 인식이 429무료 등급 사용량 한도를 넘었습니다. 잠시 뒤 다시 하거나 STT_PROVIDER 를 local·openai 로 바꿉니다.
AI 기능이 502.env 의 OPENAI_API_KEY, OpenAI 크레딧을 확인합니다. Docker 실행이면 .env 수정 후 다시 실행해야 반영됩니다. 백엔드 로그(make logs, Windows docker compose logs -f backend)에 원인이 남습니다.
Safari 에서 녹음이 안 되거나 형식 오류Safari 는 webm 대신 mp4 로 녹음합니다. 프롬프트대로 만들었다면 처리되지만, 확인은 Chrome·Edge 로 하는 것을 권장합니다.
