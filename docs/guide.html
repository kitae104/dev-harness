dev-harness 따라하기

Spring Boot + React 프로젝트를 명령 하나로 만들고, 그 위에서 Claude Code 로 일관되게 기능을 추가하는 방법을 순서대로 정리했습니다. 보라색 테두리 상자는 Claude Code 에 그대로 붙여 넣는 프롬프트, 검은 상자는 터미널 명령입니다.

★빠른 시작: GitHub 에 올린 뒤 실제 프로젝트에 쓰기

dev-harness 를 GitHub 에 올린 다음, 실제 프로젝트 하나를 시작하기까지의 전체 흐름입니다. 1~2는 PC 마다 한 번, 3~6은 프로젝트마다 합니다.

하네스는 두 곳에 있습니다. dev-harness 저장소는 프로젝트를 만드는 도구(템플릿, 생성기, /s-r-setup 스킬)이고, 실제 작업 규칙과 훅은 생성된 프로젝트 안(CLAUDE.md, .claude/)에 복사되어 들어갑니다. 그래서 생성된 프로젝트는 dev-harness 없이도 혼자 동작하고, 그 프로젝트를 GitHub 에 올리면 팀원도 같은 규칙으로 일합니다.

1. dev-harness 받기 (PC 마다 한 번)

터미널
cd ~
git clone https://github.com/kitae104/dev-harness.git

2. 스킬 설치 (PC 마다 한 번)

터미널 (macOS / Linux / Git Bash. Windows PowerShell 은 scripts\install-skills.ps1)
~/dev-harness/scripts/install-skills.sh

Claude Code 를 다시 시작하면 어느 폴더에서나 /s-r-setup 이 보입니다.

3. 새 프로젝트 만들기 (프로젝트마다)

터미널
mkdir -p ~/projects && cd ~/projects
claude
Claude Code 프롬프트 (셋 중 하나)
/s-r-setup my-shop com.kitae.myshop

FastAPI 가 필요하면 /s-r-f-setup, AI 채팅이 필요하면 /s-r-ai-setup my-shop anthropic. ~/projects/my-shop 에 첫 커밋까지 된 프로젝트가 생깁니다.

4. 실행해서 확인

터미널
cd ~/projects/my-shop
make up        # http://localhost:3000 에서 회원가입 → 로그인 → 대시보드 확인
make down      # 끝낼 때 (이 프로젝트만 종료)

5. 내 GitHub 저장소로 올리기

GitHub 에서 빈 저장소(README 없이)를 my-shop 이름으로 만든 뒤:

터미널
git remote add origin https://github.com/kitae104/my-shop.git
git push -u origin main

올리면 GitHub Actions(.github/workflows/ci.yml)가 백엔드 테스트, 프론트엔드 린트·빌드, Docker 빌드를 자동으로 돌립니다. .env 는 올라가지 않습니다(비밀값 보호).

6. 그 프로젝트에서 Claude Code 로 개발

터미널
cd ~/projects/my-shop
cd frontend && npm install && cd ..   # 린트 훅이 쓰는 도구 설치 (처음 한 번)
claude
Claude Code 프롬프트
/add-domain 게시글 (제목 필수 100자, 내용 필수, 작성자=로그인 사용자). 목록은 최신순 페이지네이션, 수정·삭제는 작성자만.

이후 자세한 사용법은 6단계, 팀원과 함께 쓰기·기존 프로젝트 적용·업데이트는 7단계를 보세요.

★VS Code 로 시작하기 (한 단계씩)

VS Code 안에서 Claude Code 확장으로 처음부터 끝까지 진행하는 순서입니다. 1~4는 PC 마다 한 번, 5~9는 프로젝트마다 합니다. Windows 와 macOS 가 다른 곳은 따로 적었습니다.

1. 프로그램 설치 (PC 마다 한 번)

프로그램메모
VS Code1.94 이상
GitWindows 는 Git for Windows 를 기본값으로 설치. 생성된 프로젝트의 훅이 Git Bash 로 실행되므로 Windows 에서는 꼭 필요합니다.
Node.js 22 LTS생성기, 훅, 프론트엔드
Docker Desktop설치 후 실행해 둡니다 (작업 표시줄이나 메뉴 막대에 고래 아이콘)
JDK 21예: Eclipse Temurin 21. 백엔드 테스트와 VS Code Java 확장용
uvFastAPI 가 들어간 프로젝트(/s-r-f-setup)에서만

설치가 끝나면 VS Code 를 열고 메뉴 Terminal → New Terminal(Ctrl+`)에서 확인합니다.

VS Code 터미널
git --version
node -v
docker compose version
java -version

2. Claude Code 확장 설치와 로그인 (PC 마다 한 번)

  1. 왼쪽 막대의 확장 아이콘(Ctrl+Shift+X, macOS Cmd+Shift+X)에서 Claude Code(게시자 Anthropic)를 찾아 설치합니다.
  2. 왼쪽 막대의 ✻ 아이콘을 누르거나 Ctrl+Esc(macOS Cmd+Esc)로 Claude 패널을 엽니다.
  3. 처음 열면 브라우저가 뜹니다. Claude 계정으로 로그인하고 VS Code 로 돌아옵니다.

확장에 Claude Code 가 들어 있어서 따로 설치할 것은 없습니다. 터미널에서 claude 명령도 쓰고 싶을 때만 CLI 를 추가로 설치합니다 (Windows PowerShell irm https://claude.ai/install.ps1 | iex, macOS curl -fsSL https://claude.ai/install.sh | bash).

코드 편집용으로 Extension Pack for Java, Spring Boot Extension Pack, Tailwind CSS IntelliSense, (FastAPI 를 쓰면) Python 확장을 함께 설치하면 편합니다. 없어도 Claude 와 하네스는 동작합니다.

3. dev-harness 받기 (PC 마다 한 번)

  1. Ctrl+Shift+P(macOS Cmd+Shift+P)로 명령 팔레트를 열고 Git: Clone 을 고릅니다.
  2. 주소에 https://github.com/kitae104/dev-harness.git 을 붙여 넣습니다. 비공개 저장소면 GitHub 로그인을 요청합니다.
  3. 저장할 위치로 사용자 홈 폴더(Windows C:\Users\내이름, macOS /Users/내이름)를 고르고, 끝나면 Open 을 누릅니다. 작업 영역을 신뢰하는지 물으면 신뢰한다고 답합니다.

4. 스킬 설치 (PC 마다 한 번)

dev-harness 가 열린 창에서 터미널(Ctrl+`)을 열고 실행합니다.

Windows (VS Code 기본 터미널인 PowerShell)
powershell -ExecutionPolicy Bypass -File scripts\install-skills.ps1
macOS
scripts/install-skills.sh

명령 팔레트에서 Developer: Reload Window 로 창을 다시 불러온 뒤, Claude 패널 입력창에 / 를 쳐서 s-r-setup 이 보이면 성공입니다.

5. 새 프로젝트 만들기 (프로젝트마다)

  1. File → Open Folder 에서 홈 폴더에 projects 폴더를 새로 만들고 그 폴더를 엽니다.
  2. Claude 패널에 아래처럼 입력합니다. Claude 가 node … generate.mjs 실행 허락을 구하면 허용합니다.
Claude 패널 (셋 중 하나)
/s-r-setup my-shop com.kitae.myshop

FastAPI 가 필요하면 /s-r-f-setup my-shop, AI 채팅이 필요하면 /s-r-ai-setup my-shop anthropic. projects/my-shop 폴더가 첫 커밋까지 된 상태로 생깁니다.

6. 생성된 프로젝트 폴더 열기 (중요)

File → Open Folder 로 projects/my-shop 을 엽니다. Claude 패널은 열린 폴더 기준으로 동작하므로, 이 창에서부터 my-shop 의 CLAUDE.md, 규칙, 훅, /add-domain, /verify 가 적용됩니다. 작업 영역 신뢰 질문에는 신뢰한다고 답합니다.

7. 처음 한 번 준비하고 실행

Windows (PowerShell)
cd frontend; npm install; cd ..
docker compose up -d --build
macOS
cd frontend && npm install && cd ..
make up

npm install 은 린트 훅이 쓰는 도구를 받는 것이라 처음 한 번만 합니다. 브라우저에서 http://localhost:3000 을 열어 회원가입 → 로그인 → 대시보드가 보이면 준비 끝입니다.

Windows PowerShell 에서 npm.ps1 파일을 로드할 수 없습니다 오류가 나면 npm.cmd install 로 실행하거나, PowerShell 에서 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned 를 한 번 실행한 뒤 다시 시도합니다.

Windows 에는 make 가 없으니 같은 일을 하는 docker compose 명령을 씁니다.

make (macOS)Windows 에서하는 일
make updocker compose up -d --build이 프로젝트만 빌드 후 실행
make downdocker compose down이 프로젝트만 종료 (DB 데이터 유지)
make logsdocker compose logs -f로그 보기
make psdocker compose ps상태 보기
make cleandocker compose down -v --rmi localDB 데이터와 이미지까지 삭제

8. Claude 패널로 기능 추가

Claude 패널
/add-domain 게시글 (제목 필수 100자, 내용 필수, 작성자=로그인 사용자). 목록은 최신순 페이지네이션, 수정·삭제는 작성자만.
  • Claude 가 파일을 고치거나 명령을 실행할 때 패널에 변경 내용과 허락 요청이 나옵니다. 확인하고 허용하면 됩니다.
  • 작업이 끝날 때 종료 훅이 바뀐 부분의 테스트와 린트를 자동으로 돌리고, 실패하면 Claude 가 이어서 고칩니다.
  • 전체를 다시 확인하려면 /verify, 바뀐 파일은 왼쪽의 소스 제어(Ctrl+Shift+G)에서 보고 커밋합니다.
  • 더 많은 프롬프트 예시는 6. 생성된 프로젝트에서 일하기에 있습니다.

9. 끝낼 때

터미널에서 make down(Windows docker compose down)으로 이 프로젝트 컨테이너만 내립니다. 다른 프로젝트는 영향을 받지 않습니다. 내 GitHub 저장소로 올리는 방법은 빠른 시작 5단계를 보세요.

0한눈에 보기

dev-harness 저장소에는 세 가지가 들어 있습니다.

구성내용
템플릿templates/s-r 기본(Spring Boot 4.1.1, Java 21, React 19, Tailwind 4, PostgreSQL 18, JWT 로그인·회원가입·랜딩, Docker Compose)과 확장 모듈 fastapi, spring-ai(2.0.1)
생성 명령/s-r-setup, /s-r-f-setup, /s-r-ai-setup 스킬과 생성기 scripts/new-project.mjs
하네스생성된 프로젝트마다 들어가는 CLAUDE.md, 폴더별 규칙, 린트·검증 훅, /add-domain, /verify, 리뷰 에이전트, CI
  1. 저장소를 받고 스킬을 한 번 설치합니다 (2~3단계).
  2. 새 프로젝트가 필요할 때마다 /s-r-setup 이름 으로 만들고 make up 으로 실행합니다 (4~5단계).
  3. 만든 프로젝트 폴더에서 Claude Code 를 열고 기능을 추가합니다. 규칙과 훅이 자동으로 적용됩니다 (6단계).
  4. 만든 프로젝트를 내 GitHub 저장소에 올리고 팀원과 함께 쓰는 방법은 7단계에 있습니다.
  5. dev-harness 자체를 다른 저장소에서 처음부터 다시 만들고 싶다면 8단계의 프롬프트를 순서대로 씁니다.

1준비물

한 번만 설치하면 됩니다.

도구용도확인 명령
Claude Code스킬 실행, 이후 개발. 터미널 CLI 또는 VS Code 확장(VS Code 로 시작하기)claude --version
Node.js 20 이상생성기, 훅, 프론트엔드node -v
Docker Desktopmake up 실행docker compose version
Git저장소, 생성된 프로젝트 첫 커밋git --version
JDK 17 이상로컬에서 백엔드 테스트 (컴파일용 JDK 21 은 Gradle 이 자동으로 받음)java -version
uv (FastAPI 쓸 때)Python 의존성, 테스트uv --version
make (선택)make up/down. 없으면 Makefile 주석의 docker compose 명령 사용make -v
Windows 는 Git for Windows(Git Bash 포함)를 꼭 설치하세요. 생성된 프로젝트의 훅이 Git Bash 에서 동작합니다. Windows 에는 make 가 없으므로 VS Code 로 시작하기 7단계의 docker compose 명령을 쓰면 됩니다.

2저장소 받기

모든 내용이 main 브랜치에 있습니다. PC 마다 한 번 받습니다.

터미널
git clone https://github.com/kitae104/dev-harness.git
cd dev-harness

비공개 저장소라면 처음 받을 때 GitHub 로그인을 요청합니다. VS Code 를 쓴다면 VS Code 로 시작하기의 "Git: Clone" 방법이 가장 쉽습니다. 이후 git pull 로 최신 템플릿과 스킬을 받습니다.

3스킬 설치

어느 폴더에서나 /s-r-setup 을 쓰려면 한 번 설치합니다. 저장소를 git pull 하면 스킬도 함께 최신이 됩니다.

macOS / Linux / Git Bash
scripts/install-skills.sh
Windows PowerShell
powershell -ExecutionPolicy Bypass -File scripts\install-skills.ps1

Claude Code 를 다시 시작하고 / 를 입력해 s-r-setup, s-r-f-setup, s-r-ai-setup 이 보이면 성공입니다. 보이지 않으면 dev-harness 폴더에서 Claude Code 를 열어 쓰거나, 환경 변수 DEV_HARNESS_HOME 에 저장소 경로를 지정하세요.

설치하지 않아도 dev-harness 폴더에서 Claude Code 를 열면 바로 쓸 수 있습니다. 이 경우 새 프로젝트는 저장소 옆 폴더(../이름)에 만들어집니다.

4새 프로젝트 만들기

프로젝트를 둘 폴더(예: ~/projects)에서 Claude Code 를 열고 아래 중 하나를 입력합니다.

명령결과
/s-r-setup my-shopSpring Boot + React + PostgreSQL, 로그인·회원가입·랜딩
/s-r-f-setup my-shop위 + FastAPI 서비스 (/api/py/**, 같은 JWT 로 인증)
/s-r-ai-setup my-bot anthropic위 기본 + Spring AI 채팅 (/api/ai/chat, /chat 화면). 제공자 openai(기본) | anthropic | ollama
Claude Code 프롬프트 (패키지와 위치까지 지정)
/s-r-setup my-shop com.kitae.myshop ~/projects/my-shop
Claude Code 프롬프트 (FastAPI 와 Spring AI 를 함께)
/s-r-f-setup my-lab 으로 만들되 Spring AI 도 같이 넣어줘. 모델은 anthropic 으로.

Claude Code 없이 터미널에서 같은 결과를 만들 수도 있습니다.

터미널
node ~/dev-harness/scripts/new-project.mjs --name my-shop --package com.kitae.myshop \
  --addons fastapi,spring-ai --ai-provider anthropic --out ~/projects/my-shop

생성되면 .env(임의의 JWT_SECRET 포함), .harness.json(어떤 템플릿·옵션으로 만들었는지), 첫 git 커밋까지 준비됩니다.

5실행과 종료

터미널 (생성된 프로젝트 폴더)
make up      # 이 프로젝트 컨테이너만 빌드 후 실행
make ps      # 상태
make logs    # 로그
make down    # 이 프로젝트만 종료 (DB 데이터 유지)
make clean   # 이 프로젝트의 DB 볼륨과 이미지까지 삭제
  • 화면 http://localhost:3000, 백엔드 http://localhost:8080/actuator/health, FastAPI 문서 http://localhost:8000/api/py/docs
  • 컨테이너·네트워크·볼륨 이름이 모두 COMPOSE_PROJECT_NAME(프로젝트 이름)으로 시작해 다른 프로젝트와 섞이지 않습니다.
  • 여러 프로젝트를 동시에 띄우려면 .env 의 DB_PORT, BACKEND_PORT, FRONTEND_PORT(필요하면 FASTAPI_PORT, OLLAMA_PORT)를 겹치지 않게 바꾸세요. 로컬 npm run dev 를 쓴다면 frontend/.env 의 VITE_API_PROXY_TARGET, VITE_FASTAPI_PROXY_TARGET 도 맞춰 주세요.
  • Spring AI: .env 에 OPENAI_API_KEY 또는 ANTHROPIC_API_KEY 를 넣고 make up. Ollama 는 처음 한 번 make ai-model. 키가 없어도 앱은 뜨고 채팅만 실패 메시지를 보여 줍니다.
.env 를 .env.example 로 덮어쓰지 마세요. 생성할 때 만든 임의 비밀값이 공개 기본값으로 바뀝니다.

6생성된 프로젝트에서 일하기

반드시 생성된 프로젝트 폴더에서 Claude Code 를 여세요. 그래야 그 프로젝트의 CLAUDE.md, 규칙, 훅이 적용됩니다.

하네스하는 일
CLAUDE.md구성, 명령, 작업 규칙 (검증 후 완료, 기능은 백엔드~화면까지, 에러 형식 하나, 비밀값은 .env 만, Docker 이름 규칙)
.claude/rules/*.mdbackend, frontend, docker, fastapi, spring-ai 별 세부 규칙. 해당 파일을 다룰 때만 적용
파일 수정 훅TS/TSX 는 oxlint, Python 은 ruff 로 고친 파일만 즉시 검사
종료 훅작업을 끝낼 때 바뀐 영역(backend/frontend/fastapi)의 테스트·린트 실행. 실패하면 Claude 가 이어서 고침 (최대 3번)
권한.env 읽기·수정 금지, make clean·git push 등은 실행 전 확인

자주 쓰는 프롬프트

도메인 기능 추가
/add-domain 게시글 (제목 필수 100자, 내용 필수, 작성자=로그인 사용자). 목록은 최신순 페이지네이션, 수정·삭제는 작성자만.
전체 검증
/verify
리뷰
code-reviewer 에이전트로 지금 변경 사항을 리뷰해 줘. 고치지 말고 문제만 심각도 순으로 알려 줘.
기능 하나를 계획부터
주문 기능을 추가하려고 해. 바로 코드 쓰지 말고 먼저 계획을 세워 줘:
- 필요한 엔티티와 관계, API 목록, 화면 목록
- 기존 user/auth 패턴과 .claude/rules 규칙 중 이번 작업에 해당하는 것
- 테스트 계획
계획을 확인한 뒤에 /add-domain 절차대로 구현해 줘.

.claude/rules/fastapi.md 를 따르고, 대시보드에 업로드 카드를 붙여 줘. pytest 로 정상·401·400 을 확인해 줘.

AI 채팅이 우리 서비스의 게시글을 검색해서 답할 수 있게 @Tool 로 게시글 검색 도구를 추가해 줘.
.claude/rules/spring-ai.md 를 따르고, 테스트는 ChatModel 을 목으로 바꿔서 작성해 줘.
검증 훅을 잠시 끄려면 HARNESS_VERIFY=off claude 로 실행합니다.

7실제 프로젝트로 키우기

생성된 프로젝트를 저장소로 관리하고, 팀원과 나누고, dev-harness 의 개선을 반영하는 방법입니다.

팀원이 처음 받을 때

.env 는 저장소에 없으므로 각자 만듭니다. 비밀값은 사람마다 새로 생성하세요.

터미널
git clone https://github.com/kitae104/my-shop.git && cd my-shop
cp .env.example .env
# .env 의 JWT_SECRET 을 아래 값으로 바꾸기 (Windows 는 Git Bash 에서)
openssl rand -base64 48
cd frontend && npm install && cd ..   # 훅·로컬 개발용
make up

그 폴더에서 claude 를 열면 저장소에 들어 있는 CLAUDE.md, 규칙, 훅, /add-domain, /verify 가 그대로 적용됩니다. 팀원에게 dev-harness 설치는 필요 없습니다.

개발 흐름 예시

기능 브랜치에서 작업하고 PR 준비
feature/board 브랜치를 만들고 /add-domain 으로 게시판을 추가해 줘.
끝나면 /verify 로 전체 검증하고, code-reviewer 에이전트 리뷰 결과까지 반영한 다음 커밋해 줘. 푸시는 내가 확인한 뒤에 할게.

이미 있는 프로젝트에 하네스만 적용

dev-harness 로 만들지 않은 Spring Boot + React 프로젝트에도 규칙과 훅만 가져올 수 있습니다. 그 프로젝트 폴더에서 Claude Code 를 열고:

Claude Code 프롬프트
~/dev-harness/templates/s-r 의 하네스(CLAUDE.md, .claude/settings.json, .claude/hooks, .claude/rules, .claude/skills, .claude/agents, .github/workflows/ci.yml)를
이 프로젝트에 맞게 옮겨 줘. 그대로 복사하지 말고:
- 먼저 이 프로젝트의 폴더 구조, 패키지, 빌드 명령, 에러 응답 형식, Docker 구성을 조사해서 차이를 표로 보여 줘.
- 규칙 문서는 이 프로젝트의 실제 코드 패턴에 맞게 고쳐 쓰고, 훅의 검증 명령과 폴더 이름도 맞춰 줘.
- 확인을 받은 뒤에 적용하고, 훅이 실제로 동작하는지 일부러 틀린 코드로 시험해 줘.

dev-harness 개선을 반영하기

  • 새로 만들 프로젝트: cd ~/dev-harness && git pull 만 하면 됩니다. 스킬은 링크로 설치되어 함께 최신이 됩니다.
  • 이미 만든 프로젝트: 자동으로 바뀌지 않습니다. .harness.json 에 만든 시점의 dev-harness 커밋이 기록되어 있으니, 아래 프롬프트로 차이를 반영합니다.
이미 만든 프로젝트에 하네스 개선 반영
../my-shop 은 .harness.json 에 기록된 대로 예전 dev-harness 로 만든 프로젝트야.
그 뒤 templates/s-r/.claude, CLAUDE.md 에 바뀐 내용을 비교해서 my-shop 에 반영할 변경 목록을 먼저 보여 주고, 확인하면 적용해 줘.

운영 배포 전에 확인할 것

  • JWT_SECRET 은 운영 전용 값으로 (서버의 환경 변수나 비밀 저장소에 보관)
  • DB 스키마: JPA_DDL_AUTO=update 대신 Flyway 같은 마이그레이션 도입 후 validate
  • HTTPS 앞단(리버스 프록시나 로드밸런서)과 실제 도메인으로 CORS_ALLOWED_ORIGINS 지정
  • 액세스 토큰만 있고 리프레시 토큰은 없습니다. 필요하면 기능으로 추가
Claude Code 프롬프트
이 프로젝트를 운영에 배포하려고 해. 위 항목(JWT 비밀값, Flyway 도입, CORS, 리프레시 토큰 필요 여부)과 보안 점검 결과를
목록으로 정리하고, 바꿔야 할 것을 우선순위대로 제안해 줘. 바로 고치지는 말고 계획만 먼저 보여 줘.

8처음부터 직접 만들기 (별도 프로젝트에서 재현)

dev-harness 와 같은 저장소를 새로 만들 때 쓰는 프롬프트입니다. 빈 GitHub 저장소를 만들어 내 PC 에 받은 뒤 그 폴더에서 Claude Code 를 열고 1번부터 차례로 넣으세요. 각 단계가 끝나면 결과를 확인하고 커밋한 뒤 다음으로 넘어갑니다.

각 프롬프트 앞에 계획 모드(Shift+Tab 두 번)로 계획을 먼저 받아 보면 방향을 잡기 쉽습니다. 버전은 작성 시점(2026-10) 기준입니다. Claude 가 최신 호환 버전을 확인하게 되어 있습니다.
1단계. 기본 템플릿
이 저장소에 재사용할 프로젝트 템플릿을 만들 거야. 먼저 templates/s-r 에 그 자체로 실행 가능한 기본 템플릿을 만들어 줘.

스택과 버전
- backend: Spring Boot 4.1.x(최신 패치), Java 21, Gradle(wrapper 포함), Spring Security + JWT(jjwt), JPA, validation, actuator, Lombok. Jackson 3(tools.jackson) 사용.
- frontend: React 19 + TypeScript + Vite + Tailwind CSS v4 + React Router, 린트는 oxlint.
- db: PostgreSQL 18 (postgres:18-alpine, 볼륨은 /var/lib/postgresql 에 마운트).
- 자리표시자 이름: 패키지 com.example.app, 프로젝트 이름 app. 나중에 생성기가 바꿀 거야.

기능
- 회원가입 POST /api/auth/signup, 로그인 POST /api/auth/login(액세스 토큰), GET /api/users/me, /actuator/health.
- 모든 에러 응답은 { status, message, errors, timestamp } 하나의 형식, 메시지는 한국어. Spring 기본 예외(잘못된 JSON, 404, 405, 403, 500)도 이 형식으로.
- 화면: 랜딩, 로그인, 회원가입, 대시보드(로그인 필요), 404. 토큰 만료(401) 시 자동 로그아웃.

Docker (중요: 같은 PC 에서 다른 프로젝트와 함께 씀)
- 프로젝트 하나 = Compose 프로젝트 하나. name, container_name, image, 네트워크·볼륨 name 이 모두 ${COMPOSE_PROJECT_NAME}- 로 시작.
- 포트는 .env 변수로 127.0.0.1 에만 바인딩. Makefile 에 up/down/ps/logs/db/clean (이 프로젝트만 대상).
- nginx 가 /api 를 백엔드로 프록시. resolver 127.0.0.11 + 변수 proxy_pass 로 컨테이너 재생성에도 502 가 안 나게, Host 는 $http_host 로.
- 헬스체크와 depends_on condition, 컨테이너는 root 가 아닌 사용자로 실행. JWT_SECRET 은 compose 에서 필수(${JWT_SECRET:?}).
- Gradle 툴체인은 foojay resolver 로 JDK 21 자동 다운로드 (Gradle 실행은 JDK 17+).

검증: backend 통합 테스트(H2), frontend lint + build 를 실제로 돌려서 통과시켜 줘. 끝나면 README 에 실행 방법과 API 표를 써 줘.
2단계. 확장 모듈과 생성기
templates/s-r 위에 덧붙이는 확장 모듈 두 개와 생성기를 만들어 줘.

생성기 scripts/new-project.mjs (Node 표준 라이브러리만)
- templates/s-r 를 복사 → 선택한 확장 모듈의 files/ 를 덮어쓰기 → 기본 템플릿 곳곳의 "@addon:<slot>" 주석 줄을 확장 모듈 addon.json 의 slots 에 연결된 조각 파일로 교체(선택 안 하면 줄 삭제, 쓰이지 않는 slot 은 오류).
- 자리표시자 com.example.app, AppApplication, app 을 파일별로 좁은 규칙으로 바꾸기(전역 치환 금지). 패키지 폴더 이동.
- 옵션: --name, --package, --addons, --ai-provider, --out, --no-git, --dry-run. 이름·패키지 검증(Java 예약어 거부).
- 임의 JWT_SECRET 으로 .env 생성, .harness.json 기록, git init + 첫 커밋(gradlew 실행 권한 포함), CRLF → LF 정규화.

확장 모듈 templates/addons/fastapi
- fastapi/ 서비스(Python 3.13, uv, pyproject + uv.lock), 경로는 모두 /api/py/**.
- Spring 이 발급한 JWT 를 같은 JWT_SECRET 으로 검증(HS256/384/512, exp·sub 필수). 에러 형식은 Spring 과 동일.
- compose 서비스(같은 이름 규칙, 헬스체크), nginx·Vite 프록시, 대시보드 확인 카드, pytest, ruff.

확장 모듈 templates/addons/spring-ai
- Spring AI 는 반드시 템플릿의 Spring Boot 버전으로 빌드된 버전을 고를 것. Maven Central 의 모듈 POM 에서 spring-boot 버전을 확인하고 BOM 으로 관리.
- 제공자 옵션 openai(기본) | anthropic | ollama. 코드는 ChatClient 만 사용, 사용자별 ChatMemory.
- POST /api/ai/chat, DELETE /api/ai/chat, /chat 화면. 키가 없어도 앱은 뜨고 채팅만 502.
- Ollama 는 이 프로젝트 전용 컨테이너 + make ai-model, spring.ai.retry 를 짧게(2회, 최대 5초). nginx 의 /api/ai/ 는 타임아웃 300초.
- 테스트는 ChatModel 을 목으로.

scripts/verify-templates.sh 로 모든 조합(base, fastapi, ai-openai, ai-anthropic, ai-ollama, all)을 실제로 생성해 backend test, frontend lint/build, fastapi pytest, docker compose config 까지 돌려 통과시켜 줘.
3단계. 생성 명령(스킬)
.claude/skills 에 /s-r-setup, /s-r-f-setup, /s-r-ai-setup 스킬을 만들어 줘.
- 각 스킬 폴더에 SKILL.md 와 generate.mjs. generate.mjs 는 자기 실제 경로(realpath)로 저장소를 찾아 scripts/new-project.mjs 를 고정된 확장 모듈로 실행하는 얇은 실행기(DEV_HARNESS_HOME 으로 덮어쓰기 가능).
- SKILL.md: 인자에서 이름·패키지·위치(·제공자)를 읽고, 이름이 없을 때만 묻기. 실패 메시지 그대로 전달, 기존 폴더는 지우지 않기. 끝나면 위치, 실행 방법, 포트 변경 안내, "생성된 폴더에서 Claude Code 를 새로 열라"는 안내.
- scripts/install-skills.sh(심볼릭 링크, Git Bash 는 정션)와 install-skills.ps1(정션, BOM 포함 UTF-8)로 ~/.claude/skills 에 설치.
- dev-harness 폴더 안에서 실행하면 새 프로젝트는 저장소 옆에 만들어지게.
4단계. 생성된 프로젝트용 하네스
templates/s-r 에 생성된 프로젝트마다 들어갈 Claude Code 하네스를 넣어 줘. 확장 모듈은 slot 과 files/ 로 자기 내용을 추가해.
- CLAUDE.md: 구성, 명령, 작업 규칙(검증 후 완료, 기능은 백엔드~화면까지 세로로, 기존 패턴 따르기, 에러 형식 하나, 비밀값은 .env 만, Docker 이름 규칙, 되돌리기 어려운 명령은 먼저 묻기). 확장 모듈 절은 @addon slot 으로.
- .claude/rules/{backend,frontend,docker}.md (paths frontmatter 로 범위 지정), 확장 모듈은 fastapi.md, spring-ai.md. 실제 코드 패턴과 일치하게.
- .claude/settings.json: .env 읽기·수정 거부, make clean·docker compose down -v·git push 는 ask, 자주 쓰는 검증 명령은 allow.
  비밀값을 출력하는 명령(docker compose config 를 -q 없이 등)은 allow 하지 않기.
- 훅(Node, Windows Git Bash 호환): PostToolUse 로 고친 파일만 oxlint/ruff, Stop 훅으로 git 기준 바뀐 영역만 테스트·린트(통과한 변경은 캐시, 연속 3번 실패하면 사람에게 넘김, HARNESS_VERIFY=off 로 끄기).
- 스킬 /add-domain(도메인 기능을 엔티티~화면~테스트까지), /verify(전체 검증 표), 서브에이전트 code-reviewer.
- .github/workflows/ci.yml (확장 모듈은 job 을 slot 으로 추가).
훅은 일부러 틀린 코드를 넣어 실제로 막히는지 확인하고, verify-templates.sh 를 다시 돌려 줘.
5단계. 마무리 점검
전체를 한 번 더 점검해 줘. 서브에이전트로 생성기, 훅, Docker 설정, 보안, 문서와 코드 불일치, Windows 사용자 문제를 나눠서 리뷰하고, 실제 문제만 고쳐 줘.
Docker 가 있으면 all 조합을 생성해서 make up 으로 띄우고 회원가입 → 로그인 → /api/py/me → /api/ai/chat 을 curl 로 확인하고,
FRONTEND_PORT 를 바꾼 두 번째 프로젝트를 동시에 띄워 서로 영향이 없는지, make down 후 데이터가 남는지, make clean 이 그 프로젝트 것만 지우는지 확인해 줘.
마지막으로 README 와 CLAUDE.md(이 저장소 작업 규칙과 검증 명령)를 정리해 줘.

9하네스 키우기 (dev-harness 저장소에서)

dev-harness 폴더에서 Claude Code 를 열고 씁니다. 저장소의 CLAUDE.md 가 확장 지점 규칙과 검증 명령을 알려 줍니다.

새 확장 모듈 추가 (예: Redis)
